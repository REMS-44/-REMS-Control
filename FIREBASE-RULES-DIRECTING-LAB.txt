REMS Control v43.2 — правила доступу для «Режисерської лабораторії»

ВАЖЛИВО: це фрагмент, який треба ОБ'ЄДНАТИ з чинними Firestore Security Rules,
а не замінювати ним весь файл правил.

Модель доступу:
• викладач/адміністратор працює після Firebase Auth;
• студент входить за довгим секретним персональним ключем у URL;
• студент може читати й змінювати тільки вже створений документ своєї роботи;
• студент НЕ може створювати нові лабораторії, видаляти їх або змінювати відгук викладача;
• публічний list для лабораторій заборонений — знання одного ключа не дозволяє переглянути інших студентів.

Приклад правил для нових колекцій:

match /rems_directing_lab_work/{labKey} {
  allow get: if true;
  allow list: if request.auth != null;
  allow create, delete: if request.auth != null;
  allow update: if request.auth != null ||
    request.resource.data.diff(resource.data).affectedKeys()
      .hasOnly(['stages', 'projectTitle', 'updatedAt', 'studentUpdatedAt']);
}

match /rems_directing_lab_feedback/{labKey} {
  allow get: if true;
  allow list, create, update, delete: if request.auth != null;
}

Колекція rems_student_schedules уже використовується чинним персональним простором REMS-44.
Для lab.html потрібен тільки get конкретного документа за ключем; нових прав на list студенту не потрібно.
